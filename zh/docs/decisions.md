# 设计决策（中文版）

> 原文：`docs/decisions.md`

| 编号 | 决策 | 原因 |
|---|---|---|
| D1 | 第一周的前端用 **Streamlit**，而不是 React + FastAPI | 一个人，离 proposal presentation 只有一周。核心逻辑是一个普通的 Python 包，以后加 FastAPI/React 层不需要重写。 |
| D2 | 暂不使用数据库：用内存中的 `TripStore`，带版本号和历史记录 | 审批的语义（检查 base_revision、重新校验、不会重复提交）已经实现并有测试；演示不需要持久化。 |
| D3 | 用**受约束的编排器**，而不是让模型自由调用工具的循环 | 本项目面向免费 / 小型开源模型。LLM 只产出一个结构化事件（经 Pydantic 校验、可重试、有规则兜底）；后端按固定顺序调用工具，并掌管状态机。不向模型开放“提交”工具。 |
| D4 | 支持任何 OpenAI 兼容的接口 + 响应缓存 | 免费服务商（Groq、OpenRouter、SiliconFlow）和本地服务（Ollama、llama.cpp）都支持这个接口；缓存让实验可复现，也节省额度。 |
| D5 | 金额用整数“分”表示；`None` 表示未知 | 避免浮点误差；未知的费用永远不当作 0，并且会让总额变成未知。 |
| D6 | 费用指标 = 因**已有订单**发生变化而额外付出的现金 | 与 Story D（¥1,150）一致。不可退的损失作为非现金的“放弃损失”单独报告。新推荐活动的门票不计入该指标。 |
| D7 | 修复方案的排序：改动程度 → 已知费用（未知费用永远不会排成最便宜）→ 交通时间 → 偏好 | 遵循 PROJECT_CONTEXT §9.4。删除的权重高于替换，替换高于平移；30 分钟以内的平移只算一半。 |
| D8 | 返程航班是锁定的，但用户明确要求延长/缩短行程时解除锁定；商家改动的预约算作“强制移动” | 用户自己的请求（或商家）正好授权了这些改动；其余锁定依然有效，与锁定冲突时返回*无解*，并给出可以放宽的选项。 |
| D9 | 标准答案手工编写，不由引擎生成 | 避免循环论证。所有方法都由同一个校验器评判。 |
| D10 | 基于规则的解析器只用于 mock 模式和兜底 | 它是一边看着试点请求一边写的，所以 mock 模式下的 `planb` 结果偏乐观；真实运行使用 LLM 解析器，是否用了兜底会记录在 `parse_method` 里。 |
